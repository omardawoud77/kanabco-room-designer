## Team checklist before public launch

1. **Integrate the live site:** Identify the live site repository and integration owner, choose the route or subdomain, and verify a specific specialist contact path for sharing a downloaded concept. The package uses Kanabco branding; approve the logo, hero, sofa references, descriptions, and media rights before using them live. It does not send a lead or store a customer photo.
2. **Confirm product claims:** Approve the two sofa images and descriptions. Keep beds, wardrobes, dressers, dressing rooms, and kitchens labeled as design concepts. Return `priceEgp: null` for every generated result until an approved pricing system is connected.
3. **Protect the API:** Keep `OPENAI_API_KEY` on the server. Put the approved hostname behind Cloudflare, configure WAF on the raw API path, real Turnstile server verification, the trusted edge-secret header, origin protection, Upstash Redis limits, and the application kill switch. Test that a direct origin request fails.
4. **Limit the bill:** The dedicated Kanabco project already has a $50 enforced monthly hard limit, 50%/80%/95% alerts, and $10 prepaid organization credits with auto-reload off. Preserve these settings. Arrange fixed server egress and key IP allowlisting, provision the server secret securely, and retain the application's daily dollar cap. Do not copy the local key into this repository or the website client.
5. **Test in staging:** Run `npm ci`, `npm run typecheck`, `npm test`, `npm run build`, and `npm audit --omit=dev`; GitHub Actions also tests the atomic Lua guards against disposable Redis 7. The package pins patched Next.js 16.3.6, and the 29 September 2026 production-dependency audit found no known advisories. The loopback route has passed real image edits with Cloudflare test keys and Redis; use `scripts/local-e2e/README.md` to reproduce that. With a small staging budget and **real** Cloudflare protection, generate and have product specialists review representative concepts from appropriate photos for all six categories, including a sofa reference. Check cost, approved claims, and whether results preserve permanent geometry and fixtures. The first direct smoke image changed the window; a later aspect-matched local result broadly preserved it, but category-wide quality is unproven. Inspect all usage fields and totals; missing or inconsistent values trigger the daily breaker.
6. **Test abuse gates:** Confirm invalid tokens, token replay, oversize uploads, direct-origin requests, bursts, Redis failure, and `AI_FEATURE_ENABLED=false` block the paid image edit. Moderation checks the photo and fixed prompt against supported categories; it does not screen every private or unsafe visual detail.
7. **Review privacy and operations:** Have the privacy owner approve the photo-processing and retention notice, then set `AI_PHOTO_PRIVACY_URL` to its public HTTPS URL; the production AI route fails closed without it and the UI links it beside the upload control. Verify the manual advisor handoff, including download and specialist contact. Route `SPEND_SPIKE`, usage-breaker, and unsettled-call logs to a monitored alert. Scan source and deployed bundles for secrets. Confirm the hosting function supports the documented image timeout.

Keep the public feature off if any security gate fails. The static `demo/index.html` shows a fictional before/after interaction and a separate result from the real protected local API. It makes no API call at page load and does not establish production model quality or public-route security.
